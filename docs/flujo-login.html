Flujo de login: main, controlador, DAO y PostgreSQL

Diagrama de secuencia del inicio de sesión en lp2_lotes siguiendo el patrón MVC + DAO.

Punto de entrada Controlador Vista Modelo Base de datos

Qué hay que entender

  1. El diálogo modal bloquea. setVisible(true) sobre un JDialog modal no retorna hasta que se llama a dispose() o se cierra la ventana. Por eso el main puede consultar la sesión justo después de new LoginController().
  2. Sesion es el punto de encuentro. El DAO guarda ahí el usuario autenticado. GUIPrincipal lo lee con Sesion.getUsuario() sin saber cómo se validó.
  3. Cada capa tiene una sola responsabilidad. La vista solo muestra componentes, el controlador coordina, el DAO accede a la base y el main decide qué ventana abrir.
  4. El controlador no abre GUIPrincipal. Así el login no depende de la ventana principal y se puede reutilizar.

Código de referencia

// Lp2_lotes.main
new LoginController();          // vuelve cuando se cierra el login
if (Sesion.estaLogeado()) {
    new GUIPrincipal().setVisible(true);
} else {
    System.exit(0);
}

Usuario de prueba

El login compara con md5(?), así que la contraseña se guarda con md5:

INSERT INTO usuarios(nombre, email, password_hash, rol)
VALUES ('Admin', 'admin@fcyt.edu.py', md5('12345'), 'ADMIN');

md5 sirve para el ejemplo didáctico, pero no es seguro para contraseñas reales. El siguiente paso es usar bcrypt.
